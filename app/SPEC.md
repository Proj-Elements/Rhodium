## Responsibility

浏览器应用覆盖总览、收支明细、固定支出、月度回顾和设置五种工作区，以及共用导航、记账/订阅表单与设置偏好。`app` 与 `components` 共同构成这一模块。

页面把月份、编辑目标、筛选和表单暂态留在客户端，使用同源 API 读取/变更账本。不可用请求需要可恢复的错误反馈；保存请求有超时，创建重试复用幂等身份；危险操作保留确认/取消路径。失效请求和切月失败不能把旧月份数据展示为新月份结果，过期编辑须展示版本冲突并要求重新读取核对。

体验使用 HeroUI v3 / HeroUI Pro，以暖白与松绿的语义 token 同时支持亮暗主题。字体与图标本地托管。分类颜色与图标在同一账本中有稳定身份，弹窗由组件库管理焦点，移动端以可用空间重排而非假设桌面宽度。

## Boundary

- 可以依赖 React、HeroUI、共享客户端取数器和纯客户端领域/格式化工具；API 与持久化边界见 `rhodium-http-api`、`rhodium-persistence`。
- 不得导入 Prisma、服务器路由实现、Node-only 模块或 `DATABASE_URL`。
- 表单校验是反馈而非安全保证；金额、分类适用性及月份写入权限以 API 为准。
- 已结算月份在界面上明确只读，不能让用户填完表单才得知月份被锁定；AppShell 在初始化及上海日期变化后显式同步到期计划，成功时通过 `rhodium:ledger-updated` 事件触发相关页面重新取数，失败显示可恢复错误。
- 报销徽标、原始金额与自付统计同时可解释；零预算与未设置预算使用不同文案。
- 完整恢复只发送备份 envelope，预检展示影响范围，提交失败保留可重试状态；不能重复附送同一份交易数组。
- 输入日期与主题偏好沿用历史 `yueyu-*` 键；创建重试仅在 `sessionStorage` 保存尚未确认的 SHA-256 请求指纹与幂等键，最多保留 128 个未确认身份，确认后移除，不能持久化完整金额、备注等明文表单内容。会话存储或摘要能力不可用时保留页面内重试能力并说明限制；无法生成安全编号时明确报错，不得使表单卡在保存中。
- 不自行实现第二套订阅业务或月份锁定规则；可展示服务端报告的状态，不能凭浏览器状态放行写入。
- 成功写入以 BroadcastChannel 广播至其他标签页，不可用时回退 storage；获得焦点或重新可见时刷新。表单提交自己读取的版本，后台刷新不能把旧草稿自动升级为新版本。
- 月度回顾显示结算变更历史，明细历史和结算历史均支持加载更早记录；切换目标、月份及关闭时中止过期请求。默认预算删除显示在导入预检中；月内扣款后暂停仍计入本月计划固定支出。
- 视觉行为改变须有针对性合同检查与真实渲染检查；交付时分别报告自动检查与实际渲染结果，不能把历史设计记录视作持续回归保护。
