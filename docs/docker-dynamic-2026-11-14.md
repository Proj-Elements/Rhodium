# Docker 动态缺陷验证：第二轮

日期：2026-11-14。基线：`30135bf`。本轮使用真实 HTTP、两个应用进程和隔离 PostgreSQL 复现，随后增加回归并修复。

## 隔离范围

- Docker 项目仍为 `rhodium-risk-20261114`，资源带 `io.rhodium.sandbox=true` 标签。
- 新增实验实例：回环端口 `3132`、`3133`，共用测试数据库 `rhodium_dynamic_round2`；每个实例内存上限 768 MiB，调度器关闭。
- 集成测试另用已标记的一次性库 `rhodium_test_risk`，不与动态实验争用清库操作。
- 生产的 `journal-app-1`、`journal-db-1` 只检查容器元数据；其 ID、镜像、启动时间、重启次数和挂载与第一轮基线一致。未访问生产账本 API、执行生产 SQL、重启或部署生产。
- 使用独立测试镜像标签 `rhodium:risk-round2-20261114`；生产镜像标签不变。凭据、原始备份和运行日志留在忽略的 `.codex/sandbox/` 下。

## 新发现与修复

| 优先级 | 实际复现 | 修复与验证 |
| --- | --- | --- |
| P1 | 合法的 11 MiB 完整备份预检返回 400；容器日志显示 Middleware 在 10 MiB 处截断，声明的 64 MiB 恢复范围实际不可用 | 两个导入 POST 在 Handler 内复用原鉴权、来源检查和限流，绕开请求体复制层。真实 11 MiB 备份完成预检、恢复、导出和重复恢复，备注逐字一致 |
| P2 | 100,000 个空账目组成的约 300 KB 请求产生 18,000,106 字节错误响应；校验遍历并构造了大量无用错误 | 批量校验达到 50 条诊断后停止继续收集，最终应答也限制诊断；同一畸形请求恢复为 2,340 字节错误响应。预览备注只截取展示样本，完整历史值仍恢复 |
| P2 | `0001-01-01T00:00:00+01:00` 导入成功，却落成公元前时间，之后 JSON 导出返回 413；`9999-12-31T23:59:59-01:00` 则触发 Prisma 500 | 除原始日期外校验 UTC 换算后的年份，两端均在写库前返回 400；有效时区偏移仍能正常往返 |
| P2 | 仅提供 `createdAt=2099-01-01T00:00:00Z` 的分类恢复成功，数据库自动更新时间却早于创建时间，导致下一次 JSON 备份被拒绝 | 未来创建时间必须同时提供不早于它的更新时间，避免导入后得到无法再次备份的数据；失败时分类数和后续导出保持正常 |
| P2 | 恢复 `version/revision=2147483647` 后，报销、删除或重开月份导致 PostgreSQL integer overflow，返回 500 | 账目和结算统一在增加版本前检查上限，返回明确的 409，保留原记录、历史及版本；已有关闭结算的无变更重放仍成功 |
| P2 | 连续 12 次匿名导入请求消耗正常导入额度，下一次携带正确凭据也收到 429 | 失败认证使用独立额度；公开健康探针也与正常读取隔离。匿名请求仍被鉴权/限流，真实持证请求可立即继续 |

这些条目按根因统计；账目/结算两处溢出没有拆成两个问题。订阅数量断言曾把 2025-01 到 2026-11 误算为 22 个月，核实应为 23，属于测试脚本错误，不计产品缺陷。

## 请求资源边界

为避免恢复 64 MiB 能力后出现无约束并行缓冲，预检和恢复在同一进程内共用一个接收额度；繁忙返回 429 和 `Retry-After`，读取前即拒绝。请求体仍受逐字节容量检查，并增加 30 秒上传期限。

- 六路并发尝试各上传 60 MiB：一路完整成功，其余五路返回 429；未出现 OOM 或进程退出。
- 未完成的上传真实等待约 30 秒后返回 408，之后新的预检可以成功，额度没有泄漏。
- 客户端中断部分上传后，下一次预检成功。
- 三次中断包含 11 MiB 备注的实际导出，随后仍可导出，临时文件/导出额度没有阻塞后续请求。
- 当前测试镜像以非 root 用户运行，真实停止的退出码为 0，重新启动后健康检查成功。

## 数据一致性与故障注入

- 两个进程同时以同一幂等键创建，仅产生一条账目；六个持有相同旧版本的编辑只有一个成功，审计历史恰为两版。
- 结算和创建请求跨进程竞争，最终关闭快照与实际账本合计一致。
- 在隔离测试库临时安装 INSERT 失败触发器，让导入在创建分类后发生真实数据库错误：分类、账目、账本变更序号全部回滚。移除触发器后原请求成功，实验触发器与函数均已移除。
- 合法大备份重复恢复不增加重复身份；非法时间戳和超大请求在进入写入前拒绝。

## 限制

本轮是有界动态实验，不代表长时间稳定性、所有 JSON 形状或真实最大规模账本都已覆盖。实际大文件验证到 60 MiB，不把它描述成精确 64 MiB 边界压测。版本上限返回可解释冲突，不扩展数据库字段位宽；已存在的异常历史元数据不自动改写，应先用 PostgreSQL 备份保全再处理。

可复核的本地证据：`.codex/sandbox/round2/` 下的 `valid-11MiB-baseline.json`、`invalid-transactions-pressure.json`、`utc-boundaries-baseline.json`、`utc-export-baseline.json`、`future-created-baseline.json`、`unauth-quota-baseline.json`、`runtime-final-results.json`、`upload-pressure.json` 以及对应测试日志。该目录不提交，避免带入凭据或实验账本；可持续执行的回归已进入正式测试文件。
