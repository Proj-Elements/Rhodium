## 已修复

| 问题 | 修复与验证 |
| --- | --- |
| 总览预算表单遗漏 `expectedVersion`，不能正常保存 | 总览在同一读快照返回预算版本；表单带版本提交，浏览器保存成功 |
| 刷新升级旧预算草稿版本，可能覆盖其他页面修改 | 草稿绑定输入起点的版本与月份；刷新保留输入，冲突必须明确清空后重填；双页面验证拒绝旧草稿 |
| 总览 `expenseCents` 与月度汇总口径不同 | 统一为含报销的账面支出；自付、预算和分类排行仍读 `outOfPocketCents` |
| 服务缺少访问鉴权 | 页面和 API 使用共享令牌，Basic/Bearer；缺失或无效配置拒绝访问；只有精确 GET/HEAD 健康检查豁免鉴权 |
| Compose 存在公开默认数据库口令 | 两份 Compose 均要求显式配置密码；没有修改现有生产角色或密码 |
| 外部 Agent/后台写入不能主动更新页面 | 写事务原子递增变更序号；可见页面每 15 秒检查，失败重试，不叠加请求；回滚不递增；首轮成功读取也校准页面，避免漏掉与初始页面读取并发的写入 |
| 导出整份备份驻留内存、缺少并发资源边界 | 私有匿名临时文件分块输出；每进程最多两个导出；取消、溢出、空闲超时和进程终止释放文件 |
| Node 原生 fetch 的 Fetch Metadata 被误认为非法浏览器请求 | 支持缺少浏览器 Site/Dest/User 的 Bearer 调用，仍校验 Host/Origin、令牌和跨站信号；真实 HTTP 回归 |
| 合法 `9999-12` 查询将年份 10000 传给 Prisma，返回 500 | DATE 查询统一使用月末日期的包含边界；覆盖 9999-12-31，确保不会丢掉月末最后一天 |
| JSON 非法 UTF-8 被替换后写入；NUL/孤立代理字符导致数据库 500 | 严格 UTF-8 解码，递归校验字符串及键名，400 拒绝，保留合法 emoji |
| 浏览器先完整读取超大导入文件，且损坏编码被静默替换 | 读取前校验 64 MiB 上限，严格解码；验证超大文件未调用读取函数 |
| URL 搜索词、分类 ID、游标和资源 ID 中 NUL 导致 500 | 在进入数据库前统一校验；真实容器复现后修复，查询及六种 ID 路由均返回 400 |

## 运行和边界

从本 worktree 管理测试环境，始终显式指定配置和 project：

```sh
docker compose --env-file .codex/sandbox/env \
  -f .codex/sandbox/compose.yml -f .codex/sandbox/restore-compose.yml \
  -p rhodium-risk-20261114 ps
```

不要在生产目录直接运行测试数据库脚本；集成测试会清空其专用数据库。

兼容性：升级需先配置访问令牌；旧消费者如果依赖总览 `expenseCents` 的自付口径，应改读 `outOfPocketCents`。数据库增加一张运行时序号表，财务备份不包含该序号。

当前仍是共享凭据的单人账本，没有多用户隔离、分级权限或用户归属审计；远程访问需要 HTTPS。限流与导出并发额度按进程计算，直接绕过应用写数据库不会触发页面变更序号。JSON 导入/恢复上限为 64 MiB，CSV 导出上限为 256 MiB，大账本使用 PostgreSQL 备份。

这轮验证不等于长期压测、真实规模 256 MiB 下载验证、主机断电恢复、异机灾备演练或生产验收；生产运行的旧镜像未包含本次修复。
