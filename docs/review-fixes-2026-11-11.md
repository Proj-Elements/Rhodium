# Rhodium 全面审查与修复

基线为 `main@b794337`。本轮按账务核心、订阅、备份、客户端、工程、额外分支六个范围审查。各实现代理先完成修复及回归用例，统一整合后才执行测试。历史草稿中的测试和安全结论不作为本轮验证结果。

## 主要缺陷与处理

| 严重度 | 原问题及影响 | 本轮处理 |
| --- | --- | --- |
| P1 | 合并备份覆盖结算快照但留下目标额外账目，导致被锁月份的合计与明细不一致 | 在同一写事务内验证最终金额、报销净预算和分类快照，冲突整体回滚 |
| P1 | 恢复订阅后补扣暂停期间的月份 | 保存订阅与分类的暂停区间，按实际扣款日排除 |
| P1 | 旧月份补账套用当前价格和扣款计划 | 保存按月生效的计划历史；未知旧价不猜测，返回持续可见的核对提示 |
| P1 | 只改备注就隐式清除报销事实 | 保留报销；金额、日期、方向变更要求先显式撤销报销 |
| P1 | 两个标签页可互相覆盖账目 | 所有交易变更校验 `expectedVersion`，过期返回 409 |
| P1 | 网络响应丢失后重试重复入账 | 创建请求支持持久幂等键，保存请求摘要及原始响应 |
| P1 | 备份恢复回退版本，旧标签页再次通过校验 | 恢复保持版本单调，业务覆盖递增；不可变历史分叉拒绝合并 |
| P2 | 独立恢复的历史领先于实体版本，持续阻塞下一次编辑或结算 | 预览和原子恢复共同校验合并后的实体引用与版本，拒绝孤立或超前历史 |
| P1 | 外站网页可向本机账本发送写请求 | 校验 Host、Origin、浏览器 Fetch Metadata；JSON 写入严格媒体类型 |
| P1 | 无登录服务本地启动默认暴露所有网卡 | 本地开发/启动绑定回环；容器宿主端口默认回环，远程访问仍需认证代理 |
| P2 | 动作字段混入完整编辑可被当作普通编辑 | 严格互斥 schema 拒绝恢复、报销、撤销报销混合请求 |
| P2 | 十六进制、指数、错误逗号被当作金额 | 十进制字符串校验并按十进制位计算分值，拒绝歧义格式 |
| P2 | 仪表盘多个查询不在同一数据库快照 | 关联读取使用 RepeatableRead 只读事务 |
| P2 | 结算分类名称与后来改名发生漂移，重新结算覆盖旧记录 | 保存分类快照、递增结算 revision 与不可变结算历史 |
| P2 | 普通交易缺少可解释的修改轨迹 | 同事务保存交易前后快照，页面可查变更历史 |
| P2 | 历史预算接口与结算展示答案不同 | 已结算月份统一采用结算预算快照 |
| P2 | 当日、趋势、当月支出和日均混用报销口径 | 预算消费统一自付口径，账面支出和报销总额明确区分 |
| P2 | 零预算展示成等待设定 | 零预算与未设预算分别展示和计算 |
| P2 | 完整备份同时发送 rows 与 transactions，翻倍触发容量限制 | 新客户端只发送一个备份 envelope |
| P2 | 导出可生成导不回去的数据，实体和交易上限不对称 | 导出校验同一恢复协议；每类备份实体最多 100,000 条，封装请求最多 64 MiB |
| P2 | 分批应用结算锁可能阻止后续交易恢复 | 完整备份在一个事务内恢复，最后应用并校验结算 |
| P2 | 未知备份版本、非月初月份和部分时间字段被宽松接受 | 版本 1/2、月份、时间、重复标识和元数据统一校验 |
| P2 | 恢复丢失 createdAt、订阅历史、审计与幂等记录 | v2 完整备份覆盖这些事实；空库恢复保留源时间 |
| P2 | 恢复发生键冲突静默丢交易 | 明确报告冲突，不将漏账作为成功 |
| P2 | 大备份一次 IN 查询超过 PostgreSQL 参数上限 | 按批预取标识、发生键和锁月，新增超过 32,767 行回归 |
| P2 | 预览无法解释覆盖量和结算冲突 | 展示新增、覆盖、未变、锁定与冲突摘要，提交时重新核对 |
| P2 | CSV 未闭合引号、重复表头、异常列数被吞掉 | 解析失败明确拒绝 |
| P2 | CSV 丢报销，公式转义破坏原始备注 | 增加报销时间，采用显式可逆编码标记；外部 CSV 不猜测剥离字符 |
| P2 | 普通导入备注限制与备份恢复互相冲突 | 普通写入限制一致，旧合法长备注仍能完整备份恢复 |
| P2 | 已结算月份可打开保存表单，切月失败留下旧金额 | 提前只读，失败隐藏旧数据并保留重试入口 |
| P2 | 上海跨午夜不刷新，订阅同步成功后首屏仍显示同步前余额 | 日期订阅加统一账本更新事件触发刷新 |
| P2 | 保存无限等待且弹窗无法退出 | 请求超时、停止等待和关闭入口，明确结果待核对 |
| P2 | 删除只能在数秒内撤销，搜索局限当前月 | 增加持久回收站、跨月搜索、游标分页和直接月份跳转 |
| P2 | 下月订阅计划被误作本月金额、状态和扣款日 | 根据实际生效计划、当前分类和暂停区间派生展示 |
| P2 | 限流信任任意转发头，Map 所谓上限并不生效 | 默认共享本机限流；明确受信代理单 IP 契约，5,000 键硬限制 |
| P2 | 后端变更被许可 UI 类型检查阻塞，嵌套 worktree 被测试扫描 | 后端独立类型配置，隔离工具目录，明确选择受影响检查 |
| P2 | 两份 Compose 和 schema 新模型未正确触发对应 CI | 补容器路径和数据库所属测试选择 |
| P2 | CI 许可包可来自其他未合并分支 | 来源绑定默认分支或当前 PR 精确 head；合并队列只信默认分支 |
| P2 | 容器密码直接拼接 URL，特殊字符破坏连接 | 运行时编码 PG 配置，保留显式 DATABASE_URL 兼容 |
| P2 | 部署示例漏许可 secret，浮动镜像和改卷名可能误导升级 | 明确 BuildKit secret、固定数据库 digest、Rhodium 本地镜像版本和旧卷复用步骤 |
| P2 | 项目说明名称、CI、导入和限流契约过期 | 产品统一 Rhodium，旧数据库标识仅作为迁移兼容说明 |

## 明确边界

产品仍是单人账本，没有身份认证；网络可达性与 Host/Origin 检查不等于认证。旧数据没有的订阅价格、分类名称和修改历史不能凭空重建；迁移保留已有交易，只有新发生的变更形成完整历史。JSON 是完整恢复格式，CSV 仅交换账目。超出应用备份容量时必须使用 PostgreSQL 数据库备份，接口明确拒绝超容量导出。
